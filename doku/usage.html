Installation

There are several ways to install and use PackSolver depending on your needs:

Global Installation

For global access to PackSolver from any directory, install it globally using Composer: 

composer global require tuxonice/packsolver

Make sure your global Composer bin directory is in your PATH to access the tool directly.

Project-specific Installation

To use PackSolver in a specific project, add it as a development dependency: 

composer require --dev tuxonice/packsolver

You can then access it via vendor/bin/packsolver in your project directory.

Requirements

  • PHP 8.0 or higher
  • Composer 2.0 or higher

Basic Usage

PackSolver is designed to be simple to use while providing powerful analysis of your Composer dependencies.

Analyzing the Current Project

To analyze the current project directory, simply run: 

packsolver

Or if installed as a project dependency: 

vendor/bin/packsolver

Analyzing a Specific Project

To analyze a different project, specify the path to the project directory: 

packsolver /path/to/project

Understanding the Output

PackSolver will display:

  • Project Information: Name and basic details about the project
  • Detected Conflicts: List of dependency conflicts found
  • Suggested Solutions: For each conflict, multiple potential solutions with confidence ratings

Advanced Usage

PackSolver offers several advanced options to customize its behavior.

JSON Output

To get the output in JSON format (useful for integration with other tools): 

packsolver --json

Verbose Mode

For more detailed information about conflicts and solutions: 

packsolver -v

Verbose mode includes additional details such as:

  • Complete dependency chains leading to conflicts
  • Version compatibility details
  • More comprehensive solution steps
  • Reasoning behind confidence ratings

Combining Options

You can combine multiple options: 

packsolver /path/to/project --json -v

Example Scenarios

Here are some common scenarios and how to use PackSolver to solve them:

Scenario 1: Upgrading a Framework

When upgrading a major framework version, you may encounter multiple dependency conflicts. 

# Analyze the project after updating the framework requirement
packsolver -v

# Apply the recommended solutions
# For example, if PackSolver suggests updating certain packages:
composer update package1 package2 --with-dependencies

# Re-run PackSolver to verify conflicts are resolved
packsolver

Scenario 2: Adding a New Package

When adding a new package causes conflicts with existing dependencies: 

# After encountering an error with composer require
packsolver

# If PackSolver suggests relaxing version constraints:
# Edit composer.json as suggested
# Then run:
composer update

Scenario 3: CI/CD Integration

You can integrate PackSolver into your CI/CD pipeline to detect dependency conflicts early: 

#!/bin/bash
# Example CI script

# Install dependencies
composer install

# Run PackSolver with JSON output
vendor/bin/packsolver --json > conflicts.json

# Check if conflicts were found
if [ "$(jq '.conflicts | length' conflicts.json)" -gt 0 ]; then
  echo "Dependency conflicts detected!"
  exit 1
fi

Troubleshooting

Common Issues

  • Missing composer.json or composer.lock

    Ensure both files exist in the project directory. If composer.lock is missing, run composer install first.

  • Permission Issues

    If installed globally, ensure the global Composer bin directory is in your PATH and you have the necessary permissions.

  • PHP Version Conflicts

    PackSolver requires PHP 8.0+. If you're using an older version, you may need to update PHP or use a compatibility package.

Getting Help

If you encounter issues not covered here, please:

  • Check the GitHub issues to see if your problem has been reported
  • Submit a new issue with detailed information about your environment and the problem
  • Include the output of packsolver -v in your issue report
